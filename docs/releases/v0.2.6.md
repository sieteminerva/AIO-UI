# v0.2.6 — the colour pass and the closed input surface

Pre-release. Same 37 packages and 76 subpath rows as `v0.2.5`; the change is ink: one
`light-dark()` token root, every component sheet deriving its colours from `--app-*`, and a lint
that refuses a raw colour literal. Beside it, the input/form surface that `v0.2.5` still carried
in its legacy shape is now closed — three removals, listed below.

`store` / `profile` / `blog` still do not exist, so the official release waits for them.

## Breaking (vs `v0.2.5`)

- **`@aio-ui/core` drops its field node types.** `iBasicInputNode`, `iFormGroupNode` and
  `InputBuilderConfigOptions` are gone. A form field node is the input schema `{ content, config }`;
  the form-owned `condition` / `then` sit beside the blocks, and `@aio-ui/form` publishes
  `FormField` / `FormNode` for a caller that needs the type.
- **`span` is removed from `iInputLayout`.** A field's width is `wide` — a percentage of the row
  (20/40/40 is exactly 20/40/40) — or absent, which means the whole row. The integer `span` and
  the 16-column grid are retired; `column` is only the line cap.
- **The repeater's count floor is gone.** `minItems` / `atMin` are replaced by `removable`
  (default `true`) and `hideOnSource`: a repeater's first row is its **source** and is never
  deletable, clones follow `removable`, and `hideOnSource` hides the source's button.

## Migration

```diff
-import type { iBasicInputNode, InputBuilderConfigOptions } from "@aio-ui/core";
+import type { FormField } from "@aio-ui/form";

-{ content: { … }, config: { options: { span: 4 } } }
+{ content: { … }, config: { wide: 40 } }

-{ minItems: 2 }
+{ removable: false }
```

`config.options` stays a deprecated lift for `select` / `dropdown` / `picker` / `radio` /
`checkbox`; `options` belongs to the field.

## Added

- **One colour root.** `light-dark()` at `:root` decides ink, surface and border; a component
  sheet derives its `--<component>-*` tokens from an `--app-*` token instead of naming a palette.
- **Spinner and skeleton derive too.** The spinner is a mask fed by `--app-spinner-content` (the
  colour comes from the token, not the artwork); the skeleton derives from the same surface tokens.
- **Theme-aware code paper.** `code-block` follows the active mode instead of pinning one paper.
- **Popup = one sheet with the control.** The menu is positioned against the field box it belongs
  to (`position-try-fallbacks: --flip-top, flip-block`), so it opens upward near the viewport edge
  and the native picker stops guessing its side.
- **Palettes on app tokens.** Article, Table, Message and Tab draw from `--app-*`;
  `theme-cyberpunk` pins dark mode, `theme-horizontal` stays a layout-only theme.
- **A colour-literal lint.** `packages/components/__tests__/colour-literals.test.ts` fails a
  component sheet that names a raw colour where a token exists.
