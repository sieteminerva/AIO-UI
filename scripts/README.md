# `scripts/`

Node CLIs that build the packages, guard the contracts, and produce a release. No dependencies
beyond Node 20 — every file is a single `.mjs` with a usage block at the top.

**Everything is dry-run by default; `--apply` (or `--write`) is what touches the disk or the
remote.** Keep that guarantee when adding a script.

Three tiers, split by what they read: `npm run check` (~12 s, typecheck + the four contract
scripts), `npm run verify` (+ tests, ~54 s), `npm run verify:pkgs` (+ `build:pkgs` and the example
builds, ~2 m). Everything that inspects emitted `dist/` belongs to the last one.

## Chains

| Goal          | Run                                                                                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Full gate     | `npm run verify` → build:pkgs → typecheck → bounds → api → version → test → gallery build                                                                     |
| Release       | `version.mjs --apply --version x.y.z` → `npm run verify` → `release.mjs --version x.y.z --apply` → `publish-releases.mjs --apply` → `publish-cdn.mjs --apply` → **manual:** `publish-release-assets.mjs --apply` with a token |
| New component | `npm run new:component <name>` → fill the template → `npm run build:pkgs` → `npm run verify`                                                                  |

## Notes

- **Two output homes, one rule:** `releases/` is a git worktree of the orphan `releases` branch
  (`scripts/releases-worktree.mjs` creates it on first use) and holds every generated artefact —
  `v<version>/` tarballs, the unpacked jsDelivr tree, the staged copy under `.stage/`. `temp/`
  is scratch only: the bundle probe, smoke sites, commit messages. `releases/` is gitignored on
  `main` because a worktree must never be tracked twice; the folder is a real checkout, not a
  hidden directory.
- `rm -rf releases/v<version>` undoes one release build; `git worktree remove releases` drops the
  checkout when the branch is abandoned.
- On Windows this repository aliases `node` to `winpty node.exe`, which dies with
  "stdout is not a tty" when output is redirected — use `node.exe` for redirected runs.
  `api.mjs --write` must not be redirected at all.
- Adding a `packages` entry means `check:api`, `version:check` and `release.mjs` all count it
  automatically; only a hardcoded list would go stale, so there is none.
